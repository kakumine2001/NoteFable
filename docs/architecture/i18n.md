# 界面语言

NoteFable 当前启用 17 种界面语言，另有第一项“自动检测”：

- 原有 4 种：`en`（English）、`zh`（简体中文）、`zh-Hant`（繁體中文）、`ja`（日本語）
- P0（6 种）：`ko`（한국어）、`es`（Español）、`fr`（Français）、`de`（Deutsch）、`pt-BR`（Português (Brasil)）、`it`（Italiano）
- P1（7 种）：`id`（Bahasa Indonesia）、`vi`（Tiếng Việt）、`th`（ไทย）、`hi`（हिन्दी）、`ar`（العربية，RTL）、`tr`（Türkçe）、`ru`（Русский）

自动项显示当前实际语言（例如“自动检测（当前：日本語）”），手动项始终使用原生语言名（含各自 `lang` 与 `dir` 隔离，混合方向下括号和标点不错乱）；对勾表示偏好，“当前语言”表示实际显示的语言，两者分开。登录用户从设置选择，访客从侧栏帮助菜单或介绍页页脚选择。界面语言独立于笔记、聊天内容、搜索词和模型输出语言，不改写用户数据。

## 选择顺序

`src/lib/i18n/locale.ts` 是网页唯一的启用语言注册表。`LOCALE_DEFINITIONS` 同时定义内部代码、原生名、BCP 47 标签、书写方向（`dir: "ltr" | "rtl"`）、匹配语言 / 脚本 / 地区和国家推断；`Locale`、`LOCALES`、`LOCALE_NAMES`、`LOCALE_TAGS`、`LOCALE_DIRS` 从它派生。`src/lib/native-language.test.ts` 检查 Android 的 `AppLanguage.Preference`、原生名、`locales_config.xml` 以及全部 17 个 `res/values*` 目录与这个注册表完全一致；`src/lib/ios-language.test.ts` 与 `src/lib/ios-strings.test.ts` 检查 iOS 的 `AppLanguage.swift`、`EmojiCatalog.swift`、`Info.plist`（`CFBundleLocalizations`）及 17 个 `<语言>.lproj/Localizable.strings` 同步一致。

1. **明确选择**：账号优先，浏览器 Cookie（`notefable-locale`）是本机选择和账号偏好的镜像。有效值严格限于 `LOCALES` 中的 17 个内部代码。
2. **浏览器 / 系统语言（仅 Auto）**：按请求的 `Accept-Language` 有效 `q` 权重降序、同权重保持原顺序。跳过通配符、`q=0`、非法或重复权重；权重必须符合 HTTP qvalue（`0` 到 `1`，最多三位小数）。
3. **保守的国家回退（仅当 `Accept-Language` 无任何支持的语言时）**：读取 `x-vercel-ip-country`：
   - `CN`、`SG` → `zh`；`TW`、`HK`、`MO` → `zh-Hant`；`JP` → `ja`；`KR` → `ko`
   - 西语主要国家（`ES`、`MX`、`AR`、`CO`、`CL`、`PE`）→ `es`；`FR` → `fr`；`DE`、`AT` → `de`；`BR` → `pt-BR`；`IT` → `it`
   - `ID` → `id`；`VN` → `vi`；`TH` → `th`；阿拉伯语主要国家（`SA`、`EG`、`AE`、`MA`、`DZ`、`JO`、`KW`、`QA`）→ `ar`；`TR` → `tr`；`RU` → `ru`
   - `US`、`GB`、`AU`、`NZ`、`IE` → `en`
   - 印度（`IN`）、瑞士（`CH`）、加拿大（`CA`）、比利时（`BE`）等多语或英语通用地区不按 IP 强行指定区域语言，保持回退到英文。
4. **默认回退**：`en`。

标签使用严格 BCP 47 校验，兼容下划线、历史代码和 ISO 639-2/3 别名（`in` → `id`，以及 `eng`、`jpn`、`chi`/`zho`/`cmn`、`kor`、`spa`、`fra`/`fre`、`deu`/`ger`、`por`、`ita`、`ind`、`vie`、`tha`、`hin`、`ara`、`tur`、`rus`）。脚本优先于地区：`zh-Hant`、`zh-TW / HK / MO` → `zh-Hant`；`zh-Hans`、`zh-CN / SG` 和 `zh` → `zh`（`zh-Hans-HK` 仍为简体）；`pt` 的任意地区（含 `pt-BR`、`pt-PT`）统一归一到已启用的 `pt-BR`。地区变化、旅行、IP 和刷新永远不会覆盖手动选择。

## 账号上的语言

`User.locale` 无需迁移：有效手动值存内部代码，`null` 表示明确的 Auto。

- `PATCH /api/account { locale: null }` 明确恢复 Auto；省略 `locale` 不修改该字段。字符串只接受 `LOCALES` 中的 17 个已启用内部代码，拒绝 `"auto"`、地区变体或未启用语言。
- `GET /api/account` 的 `user.locale: null` 是已知 Auto；读不到用户行时省略字段（`undefined`＝未知），不能当作 Auto，也不能用本机偏好覆盖账号。
- 登录时账号偏好（包括 `null`）是权威值，跨设备生效；账号尚未读到 / 未知或未登录时不改变本机选择。
- `/app` 仅有一个 `AccountLocaleSync`（组件位于 `src/components/account-button.tsx`，纯决策函数 `localeSyncAction` 在 `src/lib/locale-sync.ts`），只在账号状态变化时同步，不订阅 Cookie 变化。Android（`AppLanguage.kt`）和 iOS（`AppLanguage.swift`、`LanguageSync.swift`）沿用同一决策函数。
- 访客只保存本机 Cookie；Auto 删除 Cookie。退出登录或删除账号前中止进行中的字典请求、清除 Cookie、回到环境语言。

语言菜单（`src/components/language-menu.tsx`）是可搜索、可滚动的模态对话框，搜索匹配原生名、内部代码及 BCP 47 标签，Auto 固定在第一项。

## 路由、静态页面与按需加载

首页、`/app` 和 Android / iOS 内嵌笔记编辑页 `/note-embed` 按语言预先生成静态页面：`src/app/[locale]/page.tsx`、`src/app/[locale]/app/page.tsx`、`src/app/[locale]/note-embed/page.tsx`（`generateStaticParams` 生成全部 17 种语言，`dynamicParams = false`，布局不读 Cookie 或请求头）。单主机模式下，`src/proxy.ts` 调用 `src/lib/i18n/routing.ts` 将 `/`、`/app`、`/note-embed` rewrite 到对应语言路径，地址栏 URL 不变。分域后（[deployment.md](deployment.md)）：介绍页主机（`notefable.com`）上的 `/app`、`/{locale}/app`、`/note-embed`、`/{locale}/note-embed`、旧链接参数以及带返回标记的 `/` 会 307 重定向到工作区主机（`app.notefable.com`），其中转到工作区的重定向（`/app`、`/{locale}/app`、旧链接参数、带返回标记的 `/`）由 `src/proxy.ts`（`carryLocale`）把仅限单主机的旧 `notefable-locale` Cookie 带到两主机共用的 `Domain=notefable.com`，`/note-embed` 的重定向不带；页面显示时 `i18n-provider.tsx` 的 `migrateLocaleCookie` 再清掉残留的单主机 Cookie，之后的选择由 `writeLocaleCookie` 写到共用 Domain，且介绍页主机只放行 `/api/i18n`、不向账号写 `PATCH /api/account`；工作区主机上 `/app` 重定向到 `/`，`/` rewrite 到 `/{locale}/app`（附 `X-Robots-Tag: noindex` 并写 `notefable_app` Cookie）。`/note-embed` 接受 `?lang=<locale>`（任意已启用的 17 种语言代码），优先于 Cookie 和浏览器语言，并支持原生端通过 JS 桥（`readNativeLanguage` / `window.notefableEmbed.language(code)`）就地切换字典而不重载页面。

介绍页同时提供按语言固定的公开地址 `/{locale}`（`landingPath()`）：首屏三行主文案与页面 `<title>`（`src/lib/i18n/landing-meta.ts`）在全部 17 种语言下固定保持英文，`generateMetadata` 为每个版本输出本语言描述、`canonical` 和指向全部 17 个语言版本的 `hreflang`（不输出指向 `/` 的 `x-default`，因为 `/` 由代理重写为某语言页面且其 `canonical` 指向 `/{locale}`）；`src/app/sitemap.ts` 收录全部 17 个介绍页地址与法律页面。

服务端通过 `src/lib/i18n/messages/index.ts`（`messagesFor(locale)`）只把当前这一种语言的字典传给 `I18nProvider`，不会把全部 17 份字典打进首屏 HTML 或客户端包。切换语言时通过 `GET /api/i18n?preference=…`（`Cache-Control: private, no-store`）只拉取目标语言字典并就地替换，保留草稿、附件、会话和流式状态。根布局崩溃兜底页 `src/app/global-error.tsx` 使用按语言拆块的动态加载器 `src/lib/i18n/messages/load.ts`（`loadMessages(locale)`），只在真正出错时按需下载对应语言 chunk。

## RTL（从右到左）支持

当前 `ar`（阿拉伯语）为 RTL，其余 16 种语言为 LTR（`LOCALE_DIRS` / `localeDir()`）：

- **文档方向同步**：`I18nProvider` 在 `[data-locale-root]` 上输出 `lang` 与 `dir={dir}`，并在挂载和语言切换时同步更新 `document.documentElement.lang` 与 `document.documentElement.dir`（卸载时恢复），使挂在 `<body>` 下的 `<dialog>` 模态菜单、弹窗同样继承正确的书写方向；`global-error.tsx` 与登录验证码 HTML 邮件（`src/lib/email-login.ts`）同样输出 `dir`。
- **逻辑布局属性**：侧栏、顶栏、输入框、设置、搜索、笔记助手、历史记录与介绍页统一使用 CSS 逻辑属性（`inset-inline-*`、`margin-inline-*`、`padding-inline-*`、`border-inline-*`、`text-align: start`）与 Tailwind 逻辑工具类（`ps-*`、`pe-*`、`text-start`）。移动端抽屉在 RTL 下从右侧滑入，手势滑动关闭方向随之反转（`useSwipeDismiss` 的 `direction = 1`）。浮动菜单（语言菜单、帮助菜单、侧栏更多菜单、回答操作菜单、表情选择器）按 `dir` 镜像水平对齐锚点。
- **方向性图标镜像与保留**：返回、前进、折叠箭头、收起侧栏、移入文件夹、退出登录等方向性图标通过 `.rtl-mirror` / `[dir="rtl"]`（Android 为 `Lucide.RtlMirrored`，iOS 为 `Lucide.rtlMirrored` + `.flipsForRightToLeftLayoutDirection`）水平镜像；对勾、加号、搜索放大镜、品牌标志与模型图标不镜像。
- **阿拉伯语连写保护与双向隔离（BiDi）**：CSS 对 `:lang(ar)` 归零正负 `letter-spacing`（Android Compose 设 `letterSpacing = 0.sp`，iOS SwiftUI 在 RTL / 阿拉伯语下归零 `.tracking` / `.kerning` 并由 `NoteFableApp` 注入 `layoutDirection`），避免断开阿拉伯字母连写。代码块（`.markdown-code-shell` / `pre` / `code`）、数学公式（`.katex`）、推理档位滑块、6 位邮箱验证码输入框与邮件验证码段落显式固定 `dir="ltr"`（Android `LayoutDirection.Ltr`、iOS `.leftToRight`），保证代码、公式与数字验证码不发生字符倒置。
- **幻灯片**：编辑器的界面（缩略图带、设置栏、工具栏）随文档方向镜像，右到左时横向缩略图带和总览的拖动插入位置也按右到左计算；幻灯片画面本身（`.slide-surface`）固定按左到右的 1920 × 1080 坐标摆放，文字框用 `unicode-bidi: plaintext`，阿拉伯语等段落按内容自动从右到左排；公式和代码块固定 `dir="ltr"`（[slides.md](slides.md)）。

## 字典、编辑器与表情集成

- **Web 字典**：英文原句为键；除英文外，每种语言在 `src/lib/i18n/messages/` 下有 `<lang>.ts`（UI 文案）与 `<lang>-server.ts`（服务端错误与状态译文）；繁体中文 `zh-hant.ts` 由 `npx tsx scripts/generate-zh-hant.ts` 从 `zh.ts` 与 `zh-server.ts` 自动转换生成。转换（OpenCC `cn → twp`）与产品用语的覆盖表在 `scripts/zh-hant-terms.ts`（`toTraditional`，网页与原生的生成脚本共用，有单元测试）：OpenCC 转得不合台湾说法的词在表里固定，例如「幻灯片」→「投影片」（不是「幻燈片」）、「思维导图」→「心智圖」、「便签」→「便利貼」、「类型」→「類型」（OpenCC 会转成程序用语「型別」）；加词后重跑两个生成脚本。
- **Android 与 iOS 原生资源**：
  - Android `mobile/android/app/src/main/res/values-*/*.xml`：简体（`values-zh`）、日文（`values-ja`）维护源文件，繁体（`values-b+zh+Hant`）由 `npx tsx scripts/gen-native-zh-hant.ts` 生成，其余 13 种语言（`values-ko`、`values-es`、`values-fr`、`values-de`、`values-pt-rBR`、`values-it`、`values-in`、`values-vi`、`values-th`、`values-hi`、`values-ar`、`values-tr`、`values-ru`）由 `npx tsx scripts/gen-native-strings.ts` 从 `res/values/strings*.xml` 与 Web 字典确定性生成。
  - iOS `mobile/ios/NoteFable/Resources/<语言>.lproj/Localizable.strings`：由 `npx tsx scripts/gen-ios-strings.ts` 从 Android `res/values*/strings*.xml` 合并 `scripts/ios-strings.ts` 的 `IOS_ONLY_STRINGS`（17 种语言）确定性生成，经 `Core/Text/L10n.swift` 读取。
  - 共享 JSON 资源（Android 与 iOS 通过 `mobile/ios/project.yml` 的 `SharedAssets` 共用同一份文件）：`mobile/android/app/src/main/assets/system-text.json` 由 `npx tsx scripts/gen-native-system-text.ts` 打包全部 16 种非英文语言的服务端错误与 `SYSTEM_TEXT_TEMPLATES` 译文；`assets/emoji.json` 由 `npx tsx scripts/gen-native-emoji.ts` 生成。
- **幻灯片编辑器**：界面文案和其他网页一样在字典里（版式、主题、形状的名字用 `msg()` 标记）；Android 的“…”菜单放映 / 导出在 `res/values*/strings_slides.xml`，导出文件的保存提示（`export_file_saved` / `export_file_failed`，白板和幻灯片共用）在 `res/values*/strings_export.xml`（`values`、`values-zh`、`values-ja` 维护，其余语言和 iOS 由生成脚本生成）。幻灯片里的文字是用户内容，不翻译；主题字体只含拉丁字形，中日韩、阿拉伯、泰、天城文由系统字体补上（PPTX 里写主题字体名，PowerPoint 同样回退）。繁体中文的「投影片」来自下面的术语覆盖表。
- **BlockNote 笔记编辑器**：`src/lib/i18n/blocknote-locales.ts`（`loadBlockNoteDictionary(locale)`）与 `messages/load.ts` 一样按语言拆块懒加载编辑器菜单字典，打开笔记时只下载当前语言的字典 chunk——英文复用 `@blocknote/core` 内置字典同步就绪，其余 12 种上游内置语言由 `npx tsx scripts/gen-blocknote-locales.ts` 生成独立模块（`src/lib/i18n/blocknote-locales/*.ts`），`id`、`th`、`hi`、`tr` 四种在同一目录下提供完整自定义译文模块。
- **白板（Excalidraw）**：Excalidraw 自带的界面不用（`ui={false}`），白板的工具栏、面板、菜单、导出和导入的文案都在 Web 字典里，17 种语言都有（[whiteboard.md](whiteboard.md)）。Excalidraw 剩下的少量文字（框的默认名、读屏文字）跟着 `langCode` 走：按 `src/components/whiteboard/excalidraw-locale.ts` 把 NoteFable 的语言映射成 Excalidraw 的代码，Excalidraw 只带翻译完成度 ≥85% 的语言，没有的用英文。Excalidraw 设语言时会改 `<html lang/dir>`，`useKeepDocumentLanguage` 立刻改回 NoteFable 的设置（阿拉伯语保持 RTL）。繁体中文的「便签」按术语表成为「便利貼」。
- **表情选择器**：`src/components/full-emoji-picker.tsx` 与 `scripts/native-emoji.ts`（Android 与 iOS 共用的 `assets/emoji.json`）接入 `emoji-picker-react` 提供的全部 14 套多语言关键词数据（`en`、`zh`、`zh-Hant`、`ja`、`ko`、`es`、`fr`、`de`、`pt-BR`→`pt`、`it`、`vi`、`th`、`hi`、`ru`）；上游包未提供关键词库的 `id`、`ar`、`tr` 使用本地化界面标题 / 分类名并回退英文搜索关键词。
- **不翻译的内容**：品牌名、模型名、文件名、用户内容、AI 正文与思考摘要、上游原样错误；`/privacy`、`/terms` 与 `/delete-account` 正文保持英文（`lang="en"`），`/legal-notice` 正文保持日文（`lang="ja"`）。

## 新增第 18 种语言的步骤

1. **注册语言**：在 `src/lib/i18n/locale.ts` 的 `LOCALE_DEFINITIONS` 增加条目（`code`、`name`、`tag`、`dir`、`languages`、必要的 `scripts` / `regions` / 保守的 `countries`），如为 RTL 设 `dir: "rtl"`，如有三字母或历史代码在 `LANGUAGE_ALIASES` 补充。
2. **添加 Web 字典与按需加载**：在 `src/lib/i18n/messages/` 新增 `<lang>.ts` 与 `<lang>-server.ts`，覆盖全部 UI 键、`SYSTEM_TEXT_TEMPLATES` 和服务端消息键；在 `messages/index.ts` 与 `messages/load.ts` 登记（TypeScript `Record<Locale, …>` 会强制编译期检查）。
3. **接入编辑器与表情**：在 `src/lib/i18n/blocknote-locales/` 下新增独立字典模块（若 `@blocknote/core` 已内置则在 `scripts/gen-blocknote-locales.ts` 登记并生成，否则提供完整自定义译文模块），并在 `src/lib/i18n/blocknote-locales.ts` 的 `LOADERS` 注册按需加载；若 `emoji-picker-react` 含该语言关键词文件，在 `full-emoji-picker.tsx`、`scripts/native-emoji.ts`、Android `EmojiCatalog.kt` 和 iOS `EmojiCatalog.swift` 加入并运行 `npx tsx scripts/gen-native-emoji.ts`。
4. **同步 Android 语言枚举与生成资源**：
   - 在 `mobile/android/app/src/main/java/com/kakumine/notefable/data/AppLanguage.kt` 增加枚举项、`nativeName`、`localeFromTag` / `localeFromCountry` 规则，并在 `SystemText.kt` 补充代码归一化，在 `res/xml/locales_config.xml` 按相同顺序登记标签。
   - 在 `scripts/native-strings.ts` 的 `NATIVE_LOCALE_RES_DIRS` 与 `GENERATED_NATIVE_LOCALES` 登记资源目录名，运行 `npx tsx scripts/gen-native-strings.ts` 和 `npx tsx scripts/gen-native-system-text.ts`。
5. **同步 iOS 语言枚举、配置与生成资源**：
   - 在 `mobile/ios/NoteFable/Core/Text/AppLanguage.swift` 增加 `Preference` 与 `definitions` 规则，并在 `mobile/ios/Support/Info.plist` 的 `CFBundleLocalizations` 登记新语言的 `.lproj` 代码。
   - 在 `scripts/ios-strings.ts` 补充该语言的目录映射与 `IOS_ONLY_STRINGS` 译文，运行 `npx tsx scripts/gen-ios-strings.ts`。
6. **运行校验**：执行 `npm test`、`npm run typecheck`、`npm run lint`（以及 Android 的 `./gradlew testDebugUnitTest assembleDebug` 与 iOS Core 的 `swift test`）。`messages.test.ts`、`native-language.test.ts`、`native-system-text-asset.test.ts`、`native-emoji-asset.test.ts`、`ios-language.test.ts` 与 `ios-strings.test.ts` 会自动校验新语言的全部键完整性、占位符数量、BlockNote 字典结构与双端原生资源格式。
