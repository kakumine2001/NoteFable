# 界面语言

NoteFable 当前启用英文、简体中文、繁体中文和日文，另有第一项“自动检测”。自动项显示当前实际语言（例如“自动检测（当前：日本語）”），手动项用原生语言名；对勾表示偏好，“当前语言”表示实际显示的语言，两者分开。登录用户从设置选择，访客从侧栏帮助菜单或介绍页页脚选择。界面语言独立于笔记、聊天内容、搜索词和模型输出语言，不改写用户数据。#82 的 Phase 1 只建立偏好与架构；其余 13 种语言在字典、原生资源和本地化验证完成前不开放。

## 选择顺序

`src/lib/i18n/locale.ts` 是网页唯一的启用语言注册表。`LOCALE_DEFINITIONS` 同时定义内部代码、原生名、BCP 47 标签、匹配语言 / 脚本 / 地区和国家推断；`Locale`、`LOCALES`、`LOCALE_NAMES`、`LOCALE_TAGS` 从它派生。添加后续语言时在此加一条数据，并同时提供 Web 字典、Android 资源和编辑器等集成，不要先开放空字典。`src/lib/native-language.test.ts` 检查原生枚举、原生名和 `locales_config.xml` 与这个注册表一致。

1. 明确选择（账号优先，浏览器 Cookie 是本机选择和账号偏好的镜像）。有效 Cookie 值仍是 `en` / `zh` / `zh-Hant` / `ja`，兼容已有数据。
2. 仅在 Auto 时使用请求的 `Accept-Language`，按有效 q 权重降序、同权重保持原顺序。跳过通配符、q=0、非法 / 重复权重；权重必须为 HTTP qvalue（0 到 1，最多三位小数），不接受指数、正负号等宽松数字格式。
3. 没有支持的浏览器语言时，才用 `x-vercel-ip-country`：CN、SG → 简体，TW、HK、MO → 繁体，JP → 日文，US、GB、AU、NZ、IE → 英文。后续国家映射随对应语言的译文一起开放，不能用尚未支持的语言猜测界面。
4. 英文。

标签用严格 BCP 47 校验，兼容下划线和历史 / ISO 别名（eng、jpn、chi、zho、cmn；in 规范为 id，但 Phase 1 尚未启用印尼语）。脚本优先于地区：zh-Hant、zh-TW / HK / MO → 繁体；zh-Hans、zh-CN / SG 和 zh → 简体，zh-Hans-HK 仍是简体。未知、非法或未启用的标签跳过，继续尝试后面的语言。地区变化、旅行、IP 和刷新永远不会覆盖手动选择。

## 账号上的语言

`User.locale` 无需迁移：旧的有效手动值保持原义，旧 null 继续表示环境语言，现在也可主动选回。

- `PATCH /api/account { locale: null }` 明确恢复 Auto；省略 `locale` 不修改该字段。字符串只接受已启用的内部代码，不能存 `"auto"`、地区标签或未翻译语言。
- `GET /api/account` 的 `user.locale: null` 是已知 Auto；读不到用户行时省略字段（undefined＝未知），不能当作 Auto，也不能用本机偏好覆盖账号。
- 登录时账号偏好（包括 null）是权威值，并跨设备生效。原先“账号 null 时迁移本机手动语言”的一次性写回已移除，否则另一台设备会把明确的 Auto 重新变成手动。账号尚未读到 / 未知或未登录时不改变本机选择。
- `/app` 仅有一个 `AccountLocaleSync`，规则在 `src/lib/locale-sync.ts`。只在账号状态变化时同步，不订阅 Cookie 变化；状态过时的标签页不会把另一个标签页的选择或退出登录写回。
- 访客只保存本机 Cookie；Auto 删除 Cookie。Cookie 有效期一年，`Path=/; SameSite=Lax`，HTTPS 加 `Secure`。退出前中止字典请求、清除 Cookie、暂停同步；退出失败恢复账号偏好。
- 设置保存使用原有串行乐观更新队列；保存失败回滚原账号偏好并由同步恢复界面。字典取失败保留原字典 / Cookie，显示本地化错误，可重新选择或点“重试”（包括 Auto）；新切换和退出会取消旧请求。介绍页等待字典切换成功后保存账号（未登录的 401 / 未启用登录的 404 忽略），保存失败恢复之前的本机偏好并显示错误。

菜单是可搜索、可滚动的模态对话框，包含带标签的搜索框和 radio group。搜索匹配原生名、内部代码及 BCP 47 标签，Auto 始终在第一项。方向键 / Home / End 只移动焦点，回车 / 空格选择；Esc、外部点击及手机返回关闭，焦点回到触发按钮。宽度不超过窗口减 16px，长名称换行，列表内部滚动。当前提供四种语言 + Auto；无需为更多语言重写布局。

Android 用同样的 BCP 47 规则、账号 null / 未知语义和优先级（详见 [android-native.md](android-native.md#界面语言)）。明确偏好仍存在系统“应用语言”，Auto 清空；资源内的实际语言、API `Accept-Language`、系统提示翻译和笔记 WebView 的 `lang` 保持一致。

## 路由与静态页面

首页、`/app` 和 Android 应用内嵌的笔记编辑页 `/note-embed` 按语言预先生成静态页面：`src/app/[locale]/page.tsx`、`src/app/[locale]/app/page.tsx`、`src/app/[locale]/note-embed/page.tsx`（`generateStaticParams` 生成全部 4 种语言，`dynamicParams = false`）。`src/proxy.ts` 对 `/`、`/app` 和 `/note-embed` 的每次请求调用 `src/lib/i18n/routing.ts`，按上面的顺序选出语言，然后把请求 rewrite 到 `/{locale}`、`/{locale}/app` 或 `/{locale}/note-embed`，地址栏的 URL 不变（proxy 的 `matcher` 必须与 `LOCALIZED_PATHS` 一致，测试会比较）。只有 `/note-embed` 接受 `?lang=en|zh|zh-Hant|ja`，由 Android 应用传入自己的界面语言，优先于 Cookie 和浏览器语言；无效值被忽略。介绍页另有按语言固定的地址 `/en`、`/zh`、`/zh-Hant`、`/ja`（`landingPath()`）：它们就是静态页面 `/[locale]` 本身，不经过 proxy，所以共享出去的链接按那个语言打开，用过工作区的访客也不会被送去 `/app`。`src/app/[locale]/page.tsx` 的 `generateMetadata` 给每个版本写本语言的标题和描述、`canonical`，以及指向四个版本的 `hreflang`（`/` 是 `x-default`）；`src/app/sitemap.ts` 列出这四个地址和隐私政策、服务条款、特商法标示，`src/app/robots.ts` 指向它并不让抓 `/api/`。绝对地址取 `VERCEL_PROJECT_PRODUCTION_URL`（`siteOrigin()`；根布局的 `metadataBase` 也用它，所以 canonical 和 hreflang 输出的是完整 URL）。旧的 `/?chat=` / `message=` / `view=` / `page=` 链接也在这里带着全部参数重定向到 `/app`。用过工作区的访客（有匿名设备 Cookie `notefable_device` 或 Auth.js 登录 Cookie，只看有没有，不验签名）打开 `/` 时同样带着参数重定向到 `/app`；加 `?intro` 时不跳转，照常显示介绍页。介绍页的 logo、工作区侧栏底部帮助菜单的 “About” 项（网页和 Android）以及删除账号后的跳转都指向 `/?intro`。

`src/app/[locale]/layout.tsx` 不读 Cookie 和请求头，只根据路径参数把该语言的字典传给 `I18nProvider`。Provider 给内容加上当前语言的 `lang`，静态 HTML 中就带有正确的语言；根布局 `src/app/layout.tsx` 输出 `<html lang="en">`，Provider 挂载后将它也改成当前语言。隐私政策、服务条款是英文静态页面，特商法标示（`/legal-notice`）是日文静态页面，都不经过语言判断。

用户的选择（Cookie）由 `I18nProvider` 在浏览器端读取（挂载前视为“自动”），用于上面的同步；设置里选中的项显示 `user.locale`，null 标记 Auto，实际语言另行显示。切换时通过 `GET /api/i18n?preference=…` 获取所选语言的字典，自动模式使用同样的浏览器语言和地区规则。成功后才保存 Cookie 并替换 Provider 字典，失败则保留原语言和偏好并显示提示。此接口使用 `private, no-store`，不涉及数据库；Android 仅请求推断结果时用 `?preference=auto&format=locale`，省去 Web 字典。切换由可测试的 `src/lib/locale-switch.ts` 控制器处理（后来的请求优先，取消后旧响应不提交）。Android 笔记编辑器使用桥的 `language(code)` 就地换字典，失败在编辑页提示并可重试。切换不刷新路由，所以当前输入、附件、打开的会话及正在生成的回答保留；下次页面请求仍由 proxy 按 Cookie 选择静态页面。

## 字典和翻译

英文原句就是键；`createTranslator`（`src/lib/i18n/translate.ts`）负责回退和 `{name}` 插值。`messages/zh.ts`、`messages/ja.ts` 存界面译文，`messages/zh-server.ts`、`messages/ja-server.ts` 存服务端返回的文字的译文。繁体中文 `messages/zh-hant.ts` 由 `npx tsx scripts/generate-zh-hant.ts` 用 OpenCC（`cn` → `twp`，台湾用词）从两份简体字典生成，不手工编辑；修改简体译文后重新生成并一起提交，测试会检查生成的键和值是否一致。只有当前语言的字典作为 Provider 的数据传给浏览器。Provider 在语言不变时保持同一个 `t`。原生 Android 端没有这些字典：服务端会返回的句子和它们的中 / 日译文由 `npx tsx scripts/gen-native-system-text.ts` 打包成 `mobile/android/app/src/main/assets/system-text.json`，改了服务端的 `msg()` / `fmt()` 句子、`*-server.ts` 或 `SYSTEM_TEXT_TEMPLATES` 后重新生成（测试会检查，见 [android-native.md](android-native.md)）。

客户端通过 `useT()` 或 `useI18n()` 翻译。三种标记：

- `t("…")`：渲染时直接翻译。
- `msg("…")`：常量表里的文字和保存进状态的固定句子，保持英文，显示时再 `t()`。
- `fmt("…{name}…", { name })`：要保存或从服务端返回的、带单个变量的系统句子，键必须注册在 `SYSTEM_TEXT_TEMPLATES`。普通 `t()` 不推测句型；只有系统错误提示和工具步骤标签显式调用 `localizeSystemText(text, t)`，按模板固定首尾取出完整变量，再套进译文。模板只允许一个插槽、非空且互不重叠的固定前缀，测试会检查这些条件，不扫描普通 UI 字典。只有嵌套系统错误的 `{detail}` 继续处理；标题、搜索词、文件名等用户值保持原样。多插槽的文字必须显式 `t(key, vars)`：附件校验保留可按当前语言重新渲染的回调，上传进度保留 `{ key, vars }`。不能从完成后的文字反推多个变量，因为文件名本身也可能包含句子的分隔文字。

错误提示等状态保存英文或 API 的原文，显示时在系统提示上下文调用 `localizeSystemText`，切换语言后会跟着变；普通正文、用户标题、搜索词和文件名不调用此函数。回答中途失败时，服务端和客户端在回答末尾写入英文的 `Request failed: …`（`src/lib/failure-text.ts`），同时在 SSE 和现有 `Message.activity` JSON 中记录 `kind: "failure"` 的 `offset` 和 `detail`。`ChatMessage` 只在此元数据与原文末尾完全匹配时翻译这段系统提示，不根据自然语言猜测失败；普通 AI 回答即使包含相同句子也原样显示。旧记录没有此元数据时保留英文原文。正文存储、复制和导出始终使用原文，不改数据库结构。

完整句子要作为一个键。需要插入按键、强调或高亮时，保留 `{key}` / `{term}` 这类占位符，再在占位符的位置插入 React 节点，不要按英文语序把句子拆成碎片。

日期使用当前语言的 BCP 47 标签。BlockNote 内置菜单随界面语言使用它自带的字典（繁体用 `zhTW`），表情选择器也使用对应语言的数据和标签。

品牌名、模型名、文件名和用户自己的标题保持原样。隐私政策与服务条款正文保持英文，并标注 `lang="en"`；特商法标示正文只有日文，标注 `lang="ja"`（这是日本法律要求的表示）。AI 生成的回答和思考摘要、上游服务原样返回的错误、只给 AI 看的工具错误（`PageEditError`）不翻译。

## 出错画面与网页翻译

渲染时抛出的异常不再让整页变成 Next 默认的白屏。`src/app/[locale]/error.tsx` 接住首页、`/app` 和 `/note-embed` 内的异常，`src/app/global-error.tsx` 接住布局本身的异常。两者都显示 `AppErrorScreen`（`src/components/app-error-screen.tsx`），提供“重试”（`unstable_retry`）和“重新加载页面”；`/note-embed` 里不显示关闭翻译或扩展的提示。`[locale]/error.tsx` 在 Provider 之内，直接用当前字典。`global-error` 替代了根布局，不在 Provider 之内，而且 Next 会在每个页面加载它，所以不能静态导入字典：先按英文渲染（与服务端一致），挂载后按崩溃前页面 Provider 元素（`data-locale-root`，静态 HTML 中就带当前语言）的 `lang`、Cookie、浏览器语言的顺序选语言（`<html lang>` 在 Provider 挂载前仍是根布局的 `en`，不能用），再动态导入字典并切换。

网页翻译（Chrome 翻译、沉浸式翻译等）会改写 React 仍在更新的文字节点，可能导致更新失败。聊天输入框、笔记 AI 面板的输入框和“添加页面”对话框加了 `translate="no"`；回答正文和笔记不加，仍可翻译。

## 验证

`src/lib/i18n/*.test.ts` 验证语言优先级、繁简判断和地区回退、proxy 的 rewrite 与旧链接重定向、插值、系统模板前缀互不重叠及保留原始用户值，以及从非测试源码里提取的每个 `t("…")` / `msg("…")` / `fmt("…")` 键在三份字典中都有译文且占位符一致。新增界面文案时，同时补中文和日文译文，再重新生成繁体字典。

相关修改需运行 `npm test`、`npm run typecheck`、`npm run lint`，并在浏览器里核对首页、侧栏、手机布局和设置里的语言切换。`next build` 的输出里，`/[locale]`、`/[locale]/app` 与 `/[locale]/note-embed` 应为预渲染（●），`/privacy`、`/terms`、`/legal-notice` 应为静态（○）。
