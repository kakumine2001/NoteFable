# 界面语言

StudyMate 支持英文、简体中文、繁体中文和日文。首页导航和两个工作区的侧栏底部共用 `LanguageSelect`，匿名用户也能切换语言。界面语言与聊天内容、笔记内容及模型输出语言独立，不改写用户保存的数据。

## 选择顺序

`src/lib/i18n/locale.ts` 是语言选择规则的来源：

1. `studymate-locale` Cookie 中有效的 `en` / `zh` / `zh-Hant` / `ja`。
2. 请求的 `Accept-Language`，按有效 q 权重从高到低选择支持的语言，忽略通配符与 q=0。`zh-Hant`、`zh-TW`、`zh-HK`、`zh-MO` 对应繁体中文，`zh-Hans`、`zh-CN`、`zh-SG` 和不带地区的 `zh` 对应简体中文。
3. `x-vercel-ip-country`：CN、SG → 简体中文，TW、HK、MO → 繁体中文，JP → 日文。
4. 英文。

地区只在浏览器语言不受支持或未提供时才用到。因此人在日本、浏览器首选中文时显示中文。地区信息由 Vercel 在线上提供，本地没有这个请求头时只看 Cookie 和浏览器语言；开发时可以在 HTTP 请求里手动带上这个头来验证。

手动选项保存在当前浏览器的 Cookie，有效期一年，`Path=/; SameSite=Lax`，HTTPS 下加 `Secure`。选择“自动”会删除 Cookie，重新按浏览器语言和地区判断。偏好不写入数据库，也不随 Google 登录同步。

## 路由与静态页面

首页、`/app` 和 Android 应用内嵌的笔记编辑页 `/note-embed` 按语言预先生成静态页面：`src/app/[locale]/page.tsx`、`src/app/[locale]/app/page.tsx`、`src/app/[locale]/note-embed/page.tsx`（`generateStaticParams` 生成全部 4 种语言，`dynamicParams = false`）。`src/proxy.ts` 对 `/`、`/app` 和 `/note-embed` 的每次请求调用 `src/lib/i18n/routing.ts`，按上面的顺序选出语言，然后把请求 rewrite 到 `/{locale}`、`/{locale}/app` 或 `/{locale}/note-embed`，地址栏的 URL 不变（proxy 的 `matcher` 必须与 `LOCALIZED_PATHS` 一致，测试会比较）。只有 `/note-embed` 接受 `?lang=en|zh|zh-Hant|ja`，由 Android 应用传入自己的界面语言，优先于 Cookie 和浏览器语言；无效值被忽略。旧的 `/?chat=` / `message=` / `view=` / `page=` 链接也在这里带着全部参数重定向到 `/app`。

`src/app/[locale]/layout.tsx` 不读 Cookie 和请求头，只根据路径参数把该语言的字典传给 `I18nProvider`。Provider 给内容加上当前语言的 `lang`，静态 HTML 中就带有正确的语言；根布局 `src/app/layout.tsx` 输出 `<html lang="en">`，Provider 挂载后将它也改成当前语言。隐私政策、服务条款是英文静态页面，不经过语言判断。

用户的选择（Cookie）由 `I18nProvider` 在浏览器端读取，用来显示菜单里当前选中的项；静态页面里这一项在挂载前先显示为“自动”。切换时通过 `GET /api/i18n?preference=…` 获取所选语言的字典，自动模式使用同样的浏览器语言和地区规则。成功后才保存 Cookie 并替换 Provider 字典，失败则保留原语言和偏好并显示提示。此接口使用 `private, no-store`，不涉及数据库。切换不刷新路由，所以当前输入、附件、打开的会话及正在生成的回答保留；下次页面请求仍由 proxy 按 Cookie 选择静态页面。

## 字典和翻译

英文原句就是键；`createTranslator`（`src/lib/i18n/translate.ts`）负责回退和 `{name}` 插值。`messages/zh.ts`、`messages/ja.ts` 存界面译文，`messages/zh-server.ts`、`messages/ja-server.ts` 存服务端返回的文字的译文。繁体中文 `messages/zh-hant.ts` 由 `npx tsx scripts/generate-zh-hant.ts` 用 OpenCC（`cn` → `twp`，台湾用词）从两份简体字典生成，不手工编辑；修改简体译文后重新生成并一起提交，测试会检查生成的键和值是否一致。只有当前语言的字典作为 Provider 的数据传给浏览器。Provider 在语言不变时保持同一个 `t`。

客户端通过 `useT()` 或 `useI18n()` 翻译。三种标记：

- `t("…")`：渲染时直接翻译。
- `msg("…")`：常量表里的文字和保存进状态的固定句子，保持英文，显示时再 `t()`。
- `fmt("…{name}…", { name })`：要保存或从服务端返回的、带单个变量的系统句子，键必须注册在 `SYSTEM_TEXT_TEMPLATES`。普通 `t()` 不推测句型；只有系统错误提示和工具步骤标签显式调用 `localizeSystemText(text, t)`，按模板固定首尾取出完整变量，再套进译文。模板只允许一个插槽、非空且互不重叠的固定前缀，测试会检查这些条件，不扫描普通 UI 字典。只有嵌套系统错误的 `{detail}` 继续处理；标题、搜索词、文件名等用户值保持原样。多插槽的文字必须显式 `t(key, vars)`：附件校验保留可按当前语言重新渲染的回调，上传进度保留 `{ key, vars }`。不能从完成后的文字反推多个变量，因为文件名本身也可能包含句子的分隔文字。

错误提示等状态保存英文或 API 的原文，显示时在系统提示上下文调用 `localizeSystemText`，切换语言后会跟着变；普通正文、用户标题、搜索词和文件名不调用此函数。回答中途失败时，服务端和客户端在回答末尾写入英文的 `Request failed: …`（`src/lib/failure-text.ts`），同时在 SSE 和现有 `Message.activity` JSON 中记录 `kind: "failure"` 的 `offset` 和 `detail`。`ChatMessage` 只在此元数据与原文末尾完全匹配时翻译这段系统提示，不根据自然语言猜测失败；普通 AI 回答即使包含相同句子也原样显示。旧记录没有此元数据时保留英文原文。正文存储、复制和导出始终使用原文，不改数据库结构。

完整句子要作为一个键。需要插入按键、强调或高亮时，保留 `{key}` / `{term}` 这类占位符，再在占位符的位置插入 React 节点，不要按英文语序把句子拆成碎片。

日期使用当前语言的 BCP 47 标签。BlockNote 内置菜单随界面语言使用它自带的字典（繁体用 `zhTW`），表情选择器也使用对应语言的数据和标签。

品牌名、模型名、文件名和用户自己的标题保持原样。隐私政策与服务条款正文保持英文，并标注 `lang="en"`。AI 生成的回答和思考摘要、上游服务原样返回的错误、只给 AI 看的工具错误（`PageEditError`）不翻译。

## 验证

`src/lib/i18n/*.test.ts` 验证语言优先级、繁简判断和地区回退、proxy 的 rewrite 与旧链接重定向、插值、系统模板前缀互不重叠及保留原始用户值，以及从非测试源码里提取的每个 `t("…")` / `msg("…")` / `fmt("…")` 键在三份字典中都有译文且占位符一致。新增界面文案时，同时补中文和日文译文，再重新生成繁体字典。

相关修改需运行 `npm test`、`npm run typecheck`、`npm run lint`，并在浏览器里核对首页、侧栏、手机布局和语言切换。`next build` 的输出里，`/[locale]`、`/[locale]/app` 与 `/[locale]/note-embed` 应为预渲染（●），`/privacy`、`/terms` 应为静态（○）。
